方法

野榜找的是独立开发者个人做出来、还没被搜索引擎和榜单看见的 AI 网站。这页写清楚三件事：上哪儿找、怎么筛、怎么挑。每一周的原始数据和脚本都在 仓库 里，任何人都能自己跑一遍核对。

一、上哪儿找：去「出生登记处」，不顺着链接爬

搜索引擎靠链接发现网页。一个刚上线的个人网站没有任何入链，所以它在搜索引擎里不存在。但它一定在某个地方「登记」过出生：建仓库时填了主页地址、在社区发了一句「我做了个东西」、在托管平台新建了一个空间。野榜每周去这些地方，拉最近 7 天新出生的网址。

登记处拉什么怎么判「个人」
GitHub 新仓最近 7 天新建、带 AI 相关主题词或描述、填了 homepage 的仓库仓库属主类型是 User，不是 Organization
Show HN最近 7 天带链接的 Show HN 帖发帖人本来就是个人
Hugging Face Spaces最新建立的 Space（每周只探最新 3000 个）作者在 /api/users 查得到，查不到的是机构
V2EX 分享创造最近 30 天带 AI 关键词、带站外链接的帖发帖人本来就是个人
投稿任何人投来的网站投稿人自述

还没接上的登记处（接上就加）：证书透明日志（新域名签证书的记录，接口不稳）、Lovable / Bolt / v0 / Replit 的作品墙（没有公开接口）、Reddit r/SideProject（拒绝机器访问）、即刻 / 少数派 / 小红书「我做了」帖、面包多 / 爱发电创作者页、国内「秒哒」「扣子编程」。

二、怎么筛：四道门，全是机器跑

  1. 网址得是一个能打开用的网站。指向仓库页、文档站、应用商店、社交帖、打赏页、大厂产品域名的，不算；名字还是 test / demo / My Model 这类占位名的，不算。Hugging Face 的 Space 看的是它的应用地址（xxx.hf.space），没在跑的算打不开。
  2. 作者得是个人。GitHub 机构账号、大厂和官方账号不收；中转 / 代理 / 倒卖 API 额度的不收。
  3. 发布当天逐条打开。打不开的不收。打开后看页面有没有可操作的界面（输入框、按钮、表单、单页应用壳），只有一篇说明文字的不收。
  4. 归行业、归语言。按名字、描述、页面标题里的关键词归到 12 个行业之一；中英文按是否含中文判。

每一周公开这四道门的数字：每个登记处拉了多少候选、多少不算网站、多少不是个人、多少打不开、最后收录多少。这些数字本身就是「野生网站有多少、长在哪」的一手数据。

过了四道门的网站全部进搜索库，不挑。搜索框搜的就是这个库。

三、怎么挑：每周 20 个左右「有意思」的，六个维度

搜索库是全集，周报是精选。精选不按热度排——热度字段会把陪聊壳排第一、把真解决一个行业问题的小东西埋掉。周报按六个维度挑，每个维度 0–2 分：

维度看什么
真能用打开就能用，不是演示录像、不是等候名单
解决具体环节针对某个行业里一个具体的活，而不是「万能助手」
第一次见这个做法在这个行业里以前没见过，或者把两样东西第一次接到一起
野生一个人或两三个人做的，没有公司壳、没有融资稿
有真人用有一点真实使用痕迹（star、评论、回帖）。只当粗筛和防造假，不当主分
可核可认领能找到源头（仓库、帖子、作者页），作者能来认领

现在这六个维度的分是编辑打的，每条都写一句「为什么有意思」。打分标准会随着读者反馈每周校准，变了会在这页注明。你觉得哪条打得不对，来纠错。

四、什么时候更新

每周一发布。发现、筛选、归类、出页、出图全由脚本跑；人只做一件事：从过了四道门的网站里挑出有意思的，写一句为什么。

五、认领与纠错

  • 库里的网站是你做的：认领，署名和介绍改成你要的写法。
  • 信息有错：同一个表单选「纠错」。发布后 7 天内收到的当期改并注明，超过 7 天的下一期修正。
  • 不想被收录：同一个表单选「下榜」，照办。

六、已知的坑

  • GitHub 的 homepage 字段很多人填的是仓库自己或者文档站，这部分被第一道门拦掉，所以「候选」和「收录」差一个数量级是正常的。
  • 「有没有可操作界面」是按页面源码里的标签判的，纯服务端渲染又没有表单的内容站会被误拦；被拦的可以投稿补上。
  • 行业归类是关键词规则，会错。错了来纠。
  • 创刊号（第 1 期）用的是另一套方法：从六个技能市场拉下载量按热度排。那期保留在往期里，不删，当作对照。
